An Easypanel template for deploying [GitHub Projects Bridge](https://github.com/jaison/github-projects-bridge), a remote MCP server for GitHub Projects V2.

## Why this exists

GitHub Projects V2 is useful as a project-management backend, but AI agents need an MCP interface to interact with it as part of an agentic workflow. GitHub Projects Bridge provides that connection: it exposes project operations through MCP while keeping the server-side GitHub service token out of the MCP client.

The Easypanel template turns that bridge into a reproducible deployment with OAuth 2.1 + PKCE, persistent OAuth state, and automatic secret generation.

## What it creates

The template creates an Easypanel application from `jaison/github-projects-bridge` (branch `main`), builds its root Dockerfile, exposes internal port `80`, configures OAuth 2.1 + PKCE, generates a unique OAuth signing secret, and mounts a persistent volume at `/data`.

The service URL is derived automatically from Easypanel's `EASYPANEL_DOMAIN` variable.

## Installation inputs

| Field | Description |
| --- | --- |
| Service Name | Easypanel application name. |
| GitHub User or Organization | Login that owns the Projects V2 board. |
| GitHub Personal Access Token (classic) | Classic token with the `project` scope (**Full control of projects**). |
| GitHub OAuth App Client ID | Client ID of the OAuth App used by the bridge to authenticate allowed GitHub users. |
| GitHub OAuth App Client Secret | Client Secret of the OAuth App. |
| Allowed GitHub Users | Comma-separated GitHub logins allowed to use the bridge, for example `jaison`. |

## Before deploying

Create a GitHub OAuth App in [Developer Settings](https://github.com/settings/developers).

Use the Easypanel domain as the public HTTPS URL. The OAuth App Redirect URI must be:

```
https://YOUR-EASYPANEL-DOMAIN/oauth/github/callback
```

The template configures:

- `PUBLIC_URL=https://$(EASYPANEL_DOMAIN)`
- `OAUTH_DATA_FILE=/data/oauth-state.json`
- `OAUTH_SIGNING_SECRET` as a cryptographically random secret generated during template creation.

The bridge only uses the GitHub OAuth App for user authentication. The GitHub Projects API calls continue to use the server-side `GITHUB_TOKEN`.

## Create the GitHub token

For Projects V2 boards owned by a **personal GitHub account**, use a **Personal Access Token (classic)**. Fine-grained personal access tokens currently cannot access Projects owned by a user account.

1. Open [GitHub token settings — Tokens (classic)](https://github.com/settings/tokens).
2. Select **Generate new token (classic)**.
3. Name it, for example `GitHub Projects Bridge`.
4. Under **Select scopes**, enable `project` — **Full control of projects**. GitHub will also select `read:project`; this is expected.
5. Generate the token and copy it. GitHub displays it only once.

Do not add the `repo` scope for project-board operations alone.

For **organization-owned** Projects V2, fine-grained tokens support the organization-level **Projects** permission. Organization token policies and approval requirements may apply. Classic token access may also be restricted by the organization.

## Generated environment

| Variable | Purpose |
| --- | --- |
| `GITHUB_TOKEN` | GitHub service token used for Projects V2 GraphQL operations. |
| `GITHUB_OWNER` | GitHub user or organization that owns the projects. |
| `PUBLIC_URL` | Public HTTPS URL derived from the Easypanel domain. |
| `GITHUB_OAUTH_CLIENT_ID` | GitHub OAuth App Client ID. |
| `GITHUB_OAUTH_CLIENT_SECRET` | GitHub OAuth App Client Secret. |
| `OAUTH_ALLOWED_GITHUB_USERS` | GitHub logins allowed to use the bridge. |
| `OAUTH_SIGNING_SECRET` | Random secret generated by the template to sign bridge access tokens. |
| `OAUTH_DATA_FILE` | Persistent OAuth state path: `/data/oauth-state.json`. |
| `PORT` | Internal application port (`80`). |

There is no longer an `MCP_ACCESS_TOKEN`. MCP clients authenticate through the bridge's OAuth 2.1 + PKCE flow.

## OAuth scopes

The bridge advertises and requests these project scopes together:

- `projects:read`
- `projects:write`

This allows the ChatGPT connection to authorize read and write project operations in a single consent flow.

## Persistence

OAuth state includes registered clients, authorization codes, and hashed refresh tokens. The template mounts a persistent volume at `/data` so this state survives normal service redeployments.

The implementation assumes a single service instance. Do not run multiple independent replicas sharing the JSON state file.
